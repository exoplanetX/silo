# 编写与维护规范

## 1. 面向谁、交付什么

读者希望通过 SILO 边开发、边研究、边学习。每篇围绕一个数学对象或机制，回答：
它解决什么问题，为什么成立，代码怎样实现，怎样核验，以及可用于什么研究。
正文应在离开聊天记录后仍能独立阅读。任务执行流水放在报告中，讲解保留可迁移知识。

## 2. 固定结构

正文按以下十节编排。短篇可以精简节内内容，保留对应问题的答案。

1. **问题与学习目标**：具体触发情形、本篇要学会什么、开发背景。
2. **前置知识、符号与假设**：决策对象、目标方向、变量域、记号表、适用条件。
3. **手算例子**：最小完整实例，逐步算到结果，说明常数与符号。
4. **原理推导与正确性依据**：从原语推导；区分定义、引理、证明和直觉。
5. **算法到代码的映射**：公式对应模块/函数，关键状态、变换和恢复关系。
6. **核验与复现**：可执行小例、预期结果、测试位置、实际核验范围。
7. **研究意义与可扩展问题**：能力能支持什么工作，哪些连接尚待实现或验证。
8. **局限、反例与失效条件**：已有失败机制、数值边界、未解决问题。
9. **练习与解答入口**：基础计算、推导或反例、代码阅读、研究辨析；按需取用。
10. **开发来源与修订记录**：关联任务/报告、代码提交、核验日期、修改原因。

## 3. 文件与元信息

目录固定为 `lessons/LNNNN-short-slug/`。标题使用 `LNNNN｜中文标题`。
正文顶部用模板中的 YAML 元信息记录：`lesson_id`、`title`、`topic`、`version`、
`status`、`created`、`updated`、`verified_code`、`verified_on`、`source_tasks`。

- `verified_code` 使用实际核验的完整提交哈希；未核验时写 `null` 并保留 `draft`。
- `verified_on` 是最近一次实际核验日期；内容修改不自动刷新它。
- `updated` 是本篇最近修改日期，`version` 是讲解本身的版本，不代替代码版本。
- `source_tasks` 可有多项。建篇任务与算法实现任务应在来源表分别说明。
- `checked` 要有实际例子/依据核对记录；尚未核对的增补内容应明确标注。

常规修订保持篇目 ID 与路径，更新修订记录。数学结论或符号变化应显式写出旧约定、
新约定与适用版本；只有主题独立时另建新篇。历史合同和报告不随教学重排改写。

## 4. 数学与证据表达

先定义对象和量词，再给结论。目标方向、行方向、变量界、原始/变换坐标必须明确。
需要证明的地方给出证明或标明待证明，不能用通过几个实例代替一般结论。

分别说明：数学推导、手算答案、解析/穷举核对、外部求解器比较、实际运行结果。
本任务没有运行的检查只能标为复现建议，不能填写通过时间或新测试数。
源码链接默认指向当前文件，元信息中的提交提供版本定位；必要时用 `git show`
回看该版本。代码位置优先用文件和函数名，减少行号变化造成的失效。

讨论研究意义时，区分“已有能力”“可能连接”“待检验假设”。只有引入新结构并有
相应证据时才讨论创新；成熟基础方法的正确实现本身不自动形成论文贡献。
引用外部知识时提供可核对来源，避免把参考文献列表当成已经完整阅读的证据。

## 5. 例子、习题和答案

例子使用可手算、可重复的小数据；先链接现有示例/测试，必要时在正文放完整短代码。
标明执行目录、环境依赖和断言。理论练习使用 `L0001-E01` 这样的稳定编号；
即使以后重排练习顺序，也保留编号或提供旧编号映射。

`exercises.md` 写题意、学习目的和难度；`solutions.md` 写推导、答案及失败边界。
研究辨析题允许开放结论，但应写明判据。有限数值验证能支持算例答案，不能替代
一般证明。不要为已有成熟篇复制相同完整正文来建立第二个维护源。

## 6. 未来教材整理

先在 [总目录](CATALOG.md) 选择与重排篇目，再统一记号、前置知识和章间连接，
补齐引用与版权来源说明。课程/教材章号作为编排视图管理，保留篇目 ID 追溯开发。
图片、公式、代码例子和练习应跟随所属篇目；以后导出书稿时仍能回到原始依据。
当前采用 Markdown 积累，实际有导出需求时再选择构建工具。

## 7. 开发交付的最小要求

涉及数学或算法的任务合同写明新建/更新的篇目路径，验收至少检查：
原理、代码映射、研究意义、局限和可核对小例。报告记录篇目及实际核验。
纯同步或整理任务可以只更新目录/来源，说明不新增正文的理由。
后续规则以 [tasks/README.md](../tasks/README.md) 为任务管理依据。
