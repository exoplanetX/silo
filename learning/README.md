# SILO 开发伴学系列

这里把 SILO 开发过程中值得保留的数学原理、实现思路、研究意义和失败边界，
整理为可以反复阅读的学习材料。正文以中文讲解为主，关键术语首次出现附英文。
每篇从一个具体问题出发，连接手算、推导、代码和核验，逐步积累为专题或教材素材。

从 [总目录与阅读路线](CATALOG.md) 选择篇目。首篇是
[L0001：LP 对偶约定与最优性核验](lessons/L0001-lp-duality/README.md)。

可复用运行示例优先链接项目已有 `examples/`，回归测试继续放在 `tests/`。
不预建空章节，不提交生成 PDF、大数据、运行日志或缓存。

## 编号与两种阅读顺序

- 篇目 ID 为 `L0001`、`L0002`……，目录为 `LNNNN-short-slug/`。
- 发布新篇前扫描 `lessons/` 与总目录，选最大已用编号加一；编号与主题名发布后稳定。
- ID 表示建篇身份，不表示难度或教材章号。后补的基础篇可在主题目录中排到前面。
- 开发顺序保留“为什么此时写这一篇”；主题顺序按前置知识组织“应该怎样学”。
- 未来编书时在总目录重排章、节与选篇，不因章节重排改动篇目 ID 或原路径。

## 每次开发怎样留下学习材料

涉及模型、算法、数学约定、数值处理或正确性纠错的开发任务，应选择：

1. **新建一篇**：出现可独立讲解的新对象或机制。
2. **更新已有篇**：修正、深化或补充同一对象；记录修订与核验基线。

一篇可以承接多个原子开发任务；一个任务通常更新一篇，必要时更新相关交叉引用。
代码补丁数量与讲解篇数没有一一对应要求。纯同步、格式或目录维护任务，在报告中
记录学习材料处理及理由即可，避免为小改动重复写一篇。

任务合同应写明学习交付路径；执行报告应链接交付物、代码提交和实际核验结果。
新篇同时更新总目录；已有术语优先使用 [术语表](GLOSSARY.md)。完整写法见
[编写规范](WRITING_GUIDE.md) 和 [新篇模板](templates/lesson.md)。
