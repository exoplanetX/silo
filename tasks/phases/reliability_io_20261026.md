## 1. 原目标及本轮作用

用户已同意：固定可靠研究基线、补独立验证集、落实持续集成；随后要求把其他已讨论事项交付执行，明确延后更大模型和更广模型结构。

## 3. R1 固定研究基线与独立真值

### 3.1 基线交付

建立 `docs/research_baseline.md`，记录代码/候选身份、声明支持与实际验证范围、API/CLI、格式、容差、失败语义、复现命令和证据入口。
当前文档中把旧候选或稠密实现当作当前唯一实现的陈述应按实际版本校正；保留历史记录的日期和身份。
整理不等于增加成熟度，不用测试数、文件数或任务数推算整体完成百分比。

### 3.2 冻结先于实现

首次修改 `src/` 前，提交小型冻结输入、数学预期和独立 oracle；记录完整提交与 SHA。
冻结格式语法和比较规则也在该提交完成。接受集不得用于开发中的反复试跑；开发使用另外的手写格式单元例。
这里的“未参与调试”是操作性保留集，同一执行者可读内容，不称为真正盲测。

固定 32 个基础模型：

- 24 LP：16 optimal、4 infeasible、4 unbounded。
- 8 MILP：6 optimal、2 infeasible；其中至少4个最优例独立证明 LP 松弛有分数解且界严格优于整数最优。对应路线可预先冻结既有 `cuts=False, heuristics=False` 选项以核对基础分支；不要求默认割策略也必须分支。
- 每例1–5变量、最多8行；MILP至多3个整数变量，整数可行范围有限且每个变量至多5个候选值。
- 系数、有限界、目标常数采用小整数或分母1/2/4/8的二进制精确有理数；非零系数绝对值不超过16，有限界与常数绝对值不超过32。
- 覆盖既有 min/max、目标常数、有限上下侧、等式/区间、自由/固定/上界变量和混合整数语义；不强加新的困难结构。
- 本轮新增 LP profile 的基础接受集不含完全自由行、零变量模型或非法名称；这些另做格式拒绝测试，JSON/MPS 原支持域不缩减。

oracle 不导入 `silo`、不调用生产标准化/预处理/核验器，不从生成器参数直接抄最优值。
使用 `Fraction(value)` 保留原始二进制值，LP 用有理顶点枚举/直接原始 primal-dual 依据，MILP 枚举整数赋值并求连续剩余子问题。
不可行、无界需要针对实际原始数据验证的矛盾组合或可行锚点/改善方向，不能只凭标签或空顶点集下结论。
每例独立oracle最多20000个候选基组合、2000000次有理基本运算和30秒；构造时预估并选择能在额度内核验的实例，不以增大oracle预算填满最大维数。

浮点返回点按原始数据独立计算残差，再应用既有分量容差；不额外要求所有浮点点精确满足有理等式。
原始/对偶/互补/目标/整数容差保持既有规格。非唯一最优点比较可行性、目标及有效依据，不比较点的字节相同。
正式接受集只由独立runner读取，不注册为pytest自动收集的参数集。工具单测使用另外的微型例子，避免第一次全质量检查就提前暴露/消费正式运行额度。

### 3.3 环境准备

在隔离测试子进程中固定 BLAS/OMP/MKL 线程为1并记录实际配置；不修改用户全局环境或电源设置。
开始时一次不超过10秒的 CPU/RAM/解释器/依赖快照只作资源说明，不设新的频率配对门或安静度硬门。
不自动关闭任何用户进程、不安装宿主观察器，OneDrive保持退出。资源不足、外部超时与数学数值失败分别记录。

## 4. R2 strict SILO-LP 线性文本约定

### 4.1 公开入口

在 `silo.io` 提供：

```python
read_lp_model(path)
parse_lp(text)
write_lp_model(model, path)
model_to_lp(model)
```

CLI `optimize` 增加 `.lp`/`--format lp`，保留原 JSON/MPS 行为、schema2 和退出码。
增加 `silo convert INPUT --output OUTPUT`：输入沿用 `--format auto|json|mps|lp`，输出按 `.json/.mps/.lp` 确定；未知后缀明确拒绝。
转换不求解，`optimize --output` 继续输出解 JSON；两种输出职责不能混淆。
`optimize`原有非MPS后缀回退JSON的行为保留，新增识别`.lp`；`convert`的自动输入/输出限定已知三后缀，未知输入可显式指定格式。输入输出同一路径拒绝，先完成序列化再写文件。
无需引入统一通用导入框架或更改 Model/SolveResult。

### 4.2 语法锁定

目标是清楚定义、可被独立工具读取的线性子集，不宣称所有厂商方言兼容。
必须在 `docs/lp_format.md` 固定下列语法再实现：

- UTF-8文本；`\\`至行尾为注释；节按 Minimize/Maximize、Subject To、Bounds、Generals、Binaries、End 编排。
- 允许明确列出的常用节别名、空白/空行及表达式换行；别名清单在编码前锁定，不事后按失败文本扩张。
- 线性和表达式：正负系数、裸变量、十进制/E指数、目标常数、可选目标标签和行标签；约束左侧常数准确移到右侧，不使用 `eval`。
- 行关系 `<=`、`>=`、`=`，右端为常数。原区间行导出为带防冲突名称的上下两行；不依赖厂商不一致的双侧一行语法。
- Bounds支持双侧、单侧、fixed与free；连续/一般整数默认[0,+inf)，二元域与[0,1]取合法交集。
- 初版名称采用明确的ASCII标识符profile，例如 `[A-Za-z_][A-Za-z0-9_.]*`，排除保留关键字；非法名称明确拒绝，禁止静默改名。
- 每个变量都需在输出中显式保留身份与有效界，含零目标/零列变量；不得因去零丢掉变量。
- 重复变量项若允许合并，必须在文本数值域准确合并后统一转换，且保留变量身份；规则需预先说明。
- 数字转换沿用既有输入保护：有限性、精确整数不静默改变、非零下溢拒绝。解析器不等于任意精度求解器。
- 当前LP导出遇完全自由行或零变量模型，明确报未支持；JSON/MPS继续保留其既有能力，禁止丢行/加假变量掩盖限制。
- 二次/非线性/SOS/半连续/多目标/多场景、未知节、非法数字、矛盾或重复域声明、End后数据均明确处理并报错，不忽略。

LP的往返目标是数学等价及可解释的名称对应，不要求行列顺序、注释、模型名或区间行对象布局字节相同。
比较器从原始输入构造规范约束侧，独立核对目标方向/常数、变量界/整数格、每个有限约束侧；LP拆行映射必须显式、确定、防冲突。
JSON/MPS仍保留原有更强的往返约定，不能为迁就LP而放宽旧规则。
格式语义比较与求解核验使用两条分开的通道：前者禁止使用solver容差，有限标量按实际二进制有理值精确比较（+0/-0等同），无穷仅比较符号；后者才沿用原空间分量容差。
期望签名直接从原始payload独立构造，实际签名读取解析后的公开数据；不得调用生产标准化或writer来生成期望值。需有一次2^-39级系数或界扰动被格式比较器拒绝的反例。

### 4.3 避免读写自循环

全部32模型做JSON/MPS/LP语义往返与稳定重写；另准备6个手写LP、6个手写MPS、4个手写JSON的独立数学预期。
LP至少20个明确拒绝的文本例覆盖截断、非法标识符、非法指数/非有限/下溢、未知节、非线性、域冲突和End后数据。
读写一对来自同一实现，不能作为唯一互操作依据。

新增外部检查仅在隔离验证进程安装 `highspy==1.15.1`，对固定12个导出模型分别读取MPS/LP，共24次 `readModel/getLp`；不得调用任何优化函数。
逐变量名和约束侧核对独立解析结果，整数[0,1]与binary按数学格解释；不依赖列原顺序。
外部依赖不进入生产依赖、不被原生算法导入。当前PyPI该版提供Win/Linux cp311/cp313轮子；若不可获取，记录环境阻塞，不自动升级依赖。

## 5. R3 正式接受与修正上限

编码阶段只用开发单元例；全部局部检查通过后，锁定产品源码，再执行首次正式新接受集。

| 组 | 固定运行数（一轮） |
|---|---:|
| 32基础模型 × dense/sparse，直接原模型 | 64 |
| 预先选定8LP+4MILP × JSON/MPS/LP往返后 × dense/sparse | 72 |
| 四条独立单编辑轨迹：每条初始+一次修改 × dense/sparse | 16 warm/session |
| 四个修改后状态 × dense/sparse冷求解 | 8 |
| **一轮正式公开入口请求合计** | **160** |

四轨迹各负责RHS、变量界、增行、增列，初态选自冻结最优LP，四个新状态也先获独立真值。
核对恢复后的原模型结果、冷热一致性、可复用/重建的真实诊断；不要求提速或强加某个退化基序列。
继承界、LP界、MILP gap按现有数值协议评价，不冒充任意条件数下的精确方向安全界。

正式新集最多两轮。首次失败只能在获准的I/O或验证工具中作一次有证据的集中修正后复验；输入/真值/阈值不变，失败保留，第二轮不再称未见过的holdout。
若暴露需修改求解算法/预处理/搜索才能修复的问题，保存最小失败包，报告未达项并停止该接受路径；本合同不授权数值补丁或新算法。
仍可交付已完成的独立模块，不得把CI/基线整体标成全通过。

## 7. 次数、费用与结束线

- 原子合同总数上限1；四检查点依次完成，在合同内自主推进，结束后停止。
- 新的本地自动验证/构建/安装累计上限60分钟；不计推理写作时间，不借用或重置旧账本。
- 一次正式新集最多15分钟；LP入口10秒、MILP入口30秒、每个检查子进程有独立超时；最多两轮160请求组。
- 全项目本地质量最多2次；必要局部开发检查累计最多20批，全部计入60分钟。一个命令批内不得用循环暗增次数。
- 外部解析组一次24读，至多一次针对工具/I/O的修正重跑；无外部优化。
- 本地工件构建最多2次（首次及一次真正修正后的候选），四环境矩阵最多2轮；失败环境和工件SHA保留。
- `push-on-success`只允许一次代码/config push，固定refspec为 `HEAD:refs/heads/codex/sparse-lp-reoptimization`，不得force或更新main。现有仓库为public，该任务分支源代码同步后公开可见；这不授权merge、tag、GitHub Release或包发行。
- 远端CI整轮最多2次：首次，以及同一SHA且有证据的纯基础设施失败rerun；第二轮不允许修改代码/配置。代码或配置失败时保存未达项，不第二次push。每quality job≤20分钟、安装job≤15分钟、外部格式job≤10分钟；单轮最坏4×20+8×15+10=210 runner分钟，两轮≤420。
- 收尾文档可本地提交；其源码与已过CI提交不变时，以生产源码/工件身份关联实际run，明确最终文档提交尚未同步，不为自引用再无限触发CI。
- 网络、权限、Actions服务或依赖不可用时保存本地交付，标明CI未完成，禁止改成“本地等价即远端通过”。

本轮完成的有限条件：R1基线和冻结可复现；R2声明profile读写/CLI及互操作通过；R3原始真值/结果一致且无未解决必需失败；R4实际目标矩阵通过；伴学、报告与来源完成。
这些条件达到后即停止，不自动进入扩容、结构拓展、性能竞争、原C/D/E或下一合同。
